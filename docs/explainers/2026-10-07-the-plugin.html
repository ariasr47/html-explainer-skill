What the explainer plugin does

Reading time about 6 minutesWritten 2026-10-07For: Rodrigo, his brother, anyone who installs it

The plugin turns a spec, a decision, a status or a list of questions into a one-sitting page that opens with the answer, keeps a picture in every chapter, and can collect answers back.

What does every page do, no matter the topic?

Every page has the same five parts in the same order. Step through them below. The first step already shows the whole shape; the others light up one part at a time.

The reading tools in the rail work on every page: skim mode, one chapter at a time, a reading ruler, text size, read aloud per chapter, and keyboard shortcuts.

explainer, decision, status, spec, release, research and handover. A type adds a few required components and checker rules; it never changes the template. The checker reads the type from the page and applies the rules.

Chapter 3 of 6, about 1 minute

How does a page ask questions and collect the answers?

Before this: every page explains in five parts. A gather page keeps those parts and adds a question after the chapters that need an answer.

This is the second skill. A coworker reads, types answers into fields, and presses one button. The author pastes everyone's copies into the merge tool and sees them side by side.

  1. ExplainA chapter, as always.
  2. AskOne question, one field, a hint on what a good answer holds.
  3. TypeSaved in the reader's browser. Nothing leaves the page.
  4. Copy allOne text, question by question, in Markdown, JSON or a file.
  5. MergePaste every copy into merge.html; one table per question.

You read a chapter, answer the question under it, and move on. A bar at the bottom counts your answers. When you are done you press "Copy all answers" and paste the text wherever the author asked.

You write the questions first, then the chapters that make each question answerable. Every question has a stable id, so answers from different versions and different languages still line up in the merge tool.

collect, confirm, choose, prioritise, annotate, check, protocol, pilot, readout, recurring. Same mechanic, different answer control and merged view. A research manager's toolbox.

Chapter 4 of 6, about 1 minute

How does one page become English and Japanese?

Before this: every question carries a stable id. That id is also what lets a Japanese version merge with the English one.

The author writes the English page. A script lifts every piece of text out of it into a list. The session translates the list against a glossary. The script writes the Japanese page back with the same layout and ids.

  1. English pageFinished and checked.
  2. Lift the textEvery sentence and label, in order, into one list.
  3. TranslateA session translates the list; product names follow the glossary.
  4. Japanese pageSame layout, Japanese fonts, Japanese interface words.
English page
  • Atkinson Hyperlegible Next and Lexend
  • Line height 1.6, 62 characters a line
  • Paragraphs under 40 words
  • Skim mode, Done, Remember
Japanese page
  • BIZ UDPGothic, a universal-design face
  • Line height 1.75, about 36 characters a line, no italics
  • Paragraphs under 90 characters
  • ざっと読む, 完了, 覚える
Show the commands 
node scripts/translate.mjs extract page.html > strings.json
# a session translates strings.json into strings.ja.json
node scripts/translate.mjs apply page.html strings.ja.json --lang ja --ui assets/i18n/ui.ja.json > page.ja.html
node scripts/translate.mjs check page.html page.ja.html

The checker switches to Japanese rules on its own when the page says lang="ja": character limits instead of word limits, Japanese fonts required, italics forbidden.

Remember: one source page, a Japanese twin with the right fonts, and answers that merge across languages.

Chapter 5 of 6, about 1 minute

What is an atlas, and when do you ask for one?

Before this: explainers and gather pages are one-sitting reads. The third skill makes a reference people come back to.

An atlas explains how a codebase fits together: a system map, one example travelling through it, where data goes, what runs where.

Every claim that names code points at a file and a line. A script checks that the line exists.

  1. Read the codeOne layer at a time: backend, frontend, data, infra.
  2. Write anchored contentFile, line and revision on every claim.
  3. RenderTemplate plus the atlas add-on: map, inspector, search, permalinks.
  4. Check anchorsEvery file and line must exist at the recorded revision.
  • Current behaviourSolid. What the code does today.
  • Built but dormantAmber. Code that exists but is not switched on.
  • Adopted targetDashed. Agreed, not built. Never drawn as if it existed.

Ask for an atlas when someone new joins a codebase, when you need to decide where a change belongs, or when an architecture question keeps coming back.

Show the reference it is modelled on

The FormIntact backend atlas in the pdf-translator repository: fifteen chapters, 38 routes, 23 tables, 112 embedded sources, every claim anchored, three states kept apart, a companion skill that checks current source before answering about today. The plugin keeps those rules and drops the heavy build pipeline.

Remember: an atlas anchors every claim to a file and line, keeps three states apart, and is for codebases, not for one-off decisions.

Chapter 6 of 6, about 1 minute

How do you install it and how do you use it?

Before this: three skills, one template. Installing the plugin installs all of them at once.

  1. Add the marketplace. The GitHub repository is its own marketplace.
  2. Install the plugin. One command. Claude Code picks the three skills up on the next session.
  3. Ask in plain words. "Create an html explainer for this spec." "Make a page that asks my team these five questions." "Build an atlas of the backend."
  4. Update later. One command pulls the latest version.
Show the commands 
claude plugin marketplace add ariasr47/html-explainer-skill
claude plugin install html-explainer@html-explainer-skill
claude plugin update html-explainer@html-explainer-skill

The same commands exist as slash commands inside a session: /plugin marketplace add, /plugin install.

One loading route at a time

A standalone copy in your personal skills folder and the installed plugin would both answer to the same name. Keep one. The plugin route is the one that updates itself.

  • OfflinePages open from a file with no network. Web fonts are optional.
  • PhoneNo horizontal scrolling at 390 pixels wide.
  • Dark and lightFollows the system; a button flips it; text on colour stays readable in both.
  • PrintRail and buttons disappear; folds stay as written.

Chapter 2 of 7, about 1 minute

Skill 1: the core explainer and its page types

Before this: the foundation holds the template and the guides. The core skill is the contract that turns them into a page.

The core skill is today's skill, trimmed to under 600 words. Page types stop being prose patterns and become one short file the skill reads when it needs a type.

  • explainerUnderstand one thing. Nothing beyond the contract.
  • decisionOne decision card per ruling, recommendation marked, do-nothing stated.
  • statusTimeline with one "you are here", status board, next steps, since-last-time list.
  • specFlow of what it does, split of what changes, wireframe when UI is touched, approve or hold.
  • releaseTiles for counts that matter, before and after per theme.
  • researchEvidence strength per finding, sources in folds, open questions.
  • handoverState, in flight, next, what is a claim versus verified.

Remember: template plus contract plus one type entry makes a page; seven types fit in one short file.

Chapter 3 of 7, about 1 minute

Skill 2: gather, the page that asks and collects

Before this: the core skill makes read-only pages. Your brother's pages also ask, and that needs its own skill because it needs its own components.

Every gather page runs the same five moves. Modes change only what the answer control is and how the author sees the merged result.

  1. ExplainA chapter, as today.
  2. AskOne question, a stable id, what a good answer holds.
  3. TypeSaved in the browser. Nothing leaves the page.
  4. Copy allMarkdown, JSON or CSV. Question text verbatim.
  5. MergePaste everyone's copies into one view per question.
  • collectOpen answers after chapters. Ships first.
  • confirmUnderstood, agree or concern per chapter, with a comment.
  • choosePick an option, give a one-line reason. Tallied.
  • prioritiseRank items or spend points. Combined ranking.
  • annotateComment pins per section of a draft survey or guide.
  • checkCheck questions plus a teach-back sentence.
  • protocol, pilot, readout, recurringInterview notes, survey test, findings reactions, same questions over time.
Show the copy-all shape and the merge tool 
# <page title>: answers from <name> on <date> (<lang>)
## [q3] <question text, verbatim>
<answer>
## Not answered
[q5] <question text>

merge.html is one file. Paste or drop several copies; it groups by question id, names each respondent, tags language and date, and exports Markdown, JSON or CSV.

Remember: gather is one mechanic with ten modes; collect ships first and the rest are table rows.

Chapter 4 of 7, about 1 minute

English and Japanese from one page

Before this: gather pages carry a stable id on every question. That id is what makes a Japanese version mergeable with the English one.

English page
  • Atkinson Hyperlegible Next body, Lexend headings
  • Line height 1.6, measure 62 characters
  • Paragraph under 40 words
  • Skim mode, Done, Remember, Recap
Japanese page
  • BIZ UDPGothic body and headings, a universal-design face
  • Line height 1.75, measure about 36 em, letter spacing 0.03 em, no italics
  • Paragraph under 90 characters, sentence under 60
  • ざっと読む, 完了, 覚えておく, まとめ

Audience sets the register: coworkers in plain business Japanese, executives shorter, engineers with English terms, the public in the style of やさしい日本語.

Remember: one source, two pages, same ids, so answers merge across languages; Japanese gets its own fonts, spacing and limits.

Chapter 5 of 7, about 1 minute

Skill 3: the atlas, an architecture reference you can trust

Before this: explainers are one-sitting reads. An atlas is a reference people come back to, and it must say where every claim comes from.

The FormIntact backend atlas is the model: every claim anchored to a file and line at a recorded revision, three states kept apart, one example entity travelling through the system. The plugin keeps that and drops the heavy pipeline.

38routes in the FormIntact reference atlas
23tables, 267 columns, all anchored
3 MBfolder budget, only because sources are embedded

The add-on gives atlas pages four things the explainer lacks. A system map with each connection on its own track. An inspector that opens source with line numbers. Search. Permalinks per view.

The opening keeps the explainer contract, so a newcomer can still read an atlas in one sitting.

Show what was dropped from the FormIntact pipeline

Stack-specific inventory extractors, the screenshot verifier at five widths, the drift script and the generated companion skill. The agent reads the code and writes anchors; a 30-line script checks that each anchor exists at the recorded revision. Layers accepted: backend, frontend, data, infra, whole system. Inputs: repository, layer, the example entity to follow, and where the adopted target comes from.

Remember: read the code, write anchored content, render with the add-on, check the anchors; three states kept apart everywhere.

Chapter 6 of 7, about 1 minute

What the lean rule kept and what it cut

Before this: three skills and a shared foundation. Your rule was lean and performant with no loss of design quality, and no testing or ceremony.

Kept, because it is the product
  • Design system: tokens, components, template, fonts
  • Writing and diagram rules
  • Skim, one-chapter, dark mode
  • Gather mechanic and modes
  • Japanese block and translate script
  • Atlas add-on and anchor check
  • One checker, 50 ms, zero dependencies
Cut, because it is process
  • Reviewer agent
  • Checker hook on every write
  • Evals and example pages per type
  • Atlas screenshot verifier and drift script
  • Companion-skill generator
  • Changelog ceremony; a git tag is the release
  • Three manual reads, now "open it once"
600words maximum for the core skill
15 KBtemplate CSS, script under 6 KB
4scripts, each under 300 lines

Remember: kept the design system, the modes, gather, Japanese, the atlas visuals and one checker; cut agents, hooks, evals, verifiers and ceremony.

Chapter 7 of 7, about 1 minute

How it installs, how it gets built, and what to decide

Before this: the plugin is defined. This chapter is what you need to say yes.

  1. Add the marketplace. The repository is its own marketplace once the manifest is committed.
  2. Install the plugin. One command; your brother updates with one more.
  3. Pick one loading route. The junction at your personal skills folder and the plugin would both trigger the skill. Keep one.
Show the commands 
/plugin marketplace add ariasr47/html-explainer-skill
/plugin install html-explainer@html-explainer-skill

Your local catalog (`rodrigo-agent-skills`) can carry the same package; that stays your call.

  1. Step 0, 1 hourContrast tokens, glyphs in dots, gallery synced with your skim fix.
  2. Step 1, half a dayRestructure into the plugin layout, write types.md, fix paths.
  3. Step 2, 1.5 daysGather: collect mode, merge tool, exports; then the other modes.
  4. Step 3, up to 1 dayJapanese block, interface strings, translate script, language rules.
  5. Step 4, up to 2 daysAtlas add-on, anchor check, skill text.
One thing to check before step 1

Your pending edits in the checkout (the skim-mode fix, README notes, plugin metadata) are uncommitted. Step 1 commits them first so nothing is lost in the move.
